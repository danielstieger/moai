# Changes to the JetBrains MPS Skills

For MoAI maintainers. Agents working in an application project do not need this file.

The `mps-*` skills in `skills/` derive from the generic MPS skills JetBrains ships with the MPS MCP
(`mps_mcp_initialize_project_for_agents`). MoAI adapts them. When JetBrains releases a new version,
this list says which MoAI changes to carry over and why.

Baseline: the JetBrains originals of MPS 2026.2 (build 262.10968.569), as `mps_mcp_initialize_project_for_agents`
installs them into a project's `.claude/skills/`. MoAI v0 (`b6eec7b`, 2026-09-29) was copied from an older JetBrains
catalog, so some differences are JetBrains changes MoAI never adopted (see the last section), not MoAI edits.
Reasons marked "(inferred)" were derived from the content, since the commit messages give none.

| 2026-10-21 | `mps-node-editing/SKILL.md` (Critical Directives) | New rule "Set references by name": persistent refs only for stubs, overloads, ambiguous targets in other models and long property chains over foreign entities; repair order `stillBroken` → `FIX_REFERENCES` → quick-fixes; harvest only as last resort. | Harvesting refs with `print_node` was the default and cost many calls; refs harvested before a `SET CHILD` are dead afterwards. | 2026-10-21 | `mps-node-editing/SKILL.md` (Critical Directives) | New rule "Replace referenced members through their body": constructors and test methods only via `body`; methods that call each other are replaced together. | `SET CHILD` assigns new IDs and breaks persistent refs to the replaced member. |

| 2026-10-21 | `mps-node-editing/SKILL.md` (Node factories) | New point: set every value that matters explicitly, even the default. | Verified in `mjfuhrpark2`: a value set in the blueprint is kept, a value left out gets the factory's default (`DateLiteral.fromServer=true` turned a fixed date into the server date in run 3). |

| 2026-10-21 | `mps-node-editing/SKILL.md` (Common Workflow 5), `mps-mcp-workflow/references/analysis-tools.md` (check report) | Large check reports are read with `moai/tools/dump.py problems`. | Context consumption (Z7): a 47 KB full-tree report shrinks to a few lines; `mps_dump.py` has no reader for check reports. |
| 2026-10-21 | `mps-node-editing/references/staged-construction.md` | Step "Harvest refs" renamed to "Read child refs" (refs for the following `ADD`/`SET CHILD` calls); references between nodes by name. | Consistency with the reference rule. |
| 2026-10-21 | `mps-baselanguage/SKILL.md`, `references/json-ast-workflow.md`, `critical-rules.md`, `troubleshooting.md`, `stub-references.md` | Harvesting replaced by the reference rule of `mps-node-editing`; former steps "Auto-resolution" and "Repair" merged into "References". | The skills contradicted each other (harvest vs. names); one rule in one place. |
| 2026-10-21 | `mps-baselanguage/SKILL.md` (Choose Your Path, "MoWare DSL roots") | Bodies in ObjectFlow and ManMap roots are written as Java with markers and converted with `moai/tools/text2of.py`; JSON blueprints for such bodies are no longer the path. | MoAI tooling (`maintenance/TOOLING.md`, stage 2): the parser alone resolves no business properties, status, `#` calls or MoWare literals; hand-built JSON bodies were the largest cost in runs 3 and 4. |

## Open at the next JetBrains merge

JetBrains 2026.2 content MoAI has not adopted. Decide deliberately each time:

- Sub-folder splits of references: `mps-mcp-workflow` `analysis-tools/`, `reference-formats/`; `mps-baselanguage` `parse-java-tips/`; `mps-model-manipulation` `smodel-concepts-catalog/`, `java-parser-capabilities/`. MoAI keeps single files.
- `mps-mcp-workflow/references/module-facet-settings.md`.
- `mps-language-analysis/scripts/concept_shape.py` (front end for `mps_dump.py shape`).
- `mps-node-editing/scripts/table_to_bulk_insert.py`.
- Old JetBrains text MoAI still keeps although 2026.2 dropped it: "Implicit Return" in `mps-baselanguage/references/critical-rules.md`; `UndefinedType` as `type` child of `InferredClosureParameterDeclaration` (`mps-model-manipulation`, `moai:baselanguage-collections-dsl`). Check whether still valid.
