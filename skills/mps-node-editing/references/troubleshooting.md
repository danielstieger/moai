# Node Editing — Troubleshooting

* **`Cannot invoke "JsonElement.getAsString()" because ... is null`**: a required JSON field (like `concept` or `role`) is missing.
* **Notation mismatch**: user-provided textual code may differ from the canonical JSON structure; always map it to the structure defined by the concept.
* **`Unknown property '...'` / `Unknown child role '...'` / `Unknown reference role '...'`**: the JSON blueprint uses a property name or role name that is not defined on the specified concept. Check spelling or use `mps_mcp_get_concept_details` to verify the concept's structure. A whole burst of `Unknown property …` for names the concept does declare means its language descriptor is hollow (`descriptorStatus: "hollow"`): the MoWare languages are shipped, so report a broken installation or build to the user instead of rebuilding the language.
* **`Input file path '...' is not inside the system temp directory`**: every blueprint tool accepts a file only under the JVM system temp directory — `$TMPDIR` (or `/tmp`) on Linux, `%TEMP%` on Windows; a leading `$TMPDIR` or `%TEMP%` is expanded. Copy the file there (`f="${TMPDIR:-/tmp}/blueprint-$$.json"`) or pass the JSON inline (≤ 4 KB). Not a blueprint error.
* **`Concept assignability error at JSON path '…'`**: the node, or the reference target, at that path has a concept the role does not accept. Read the lines after `Role:` before looking anything up. ` - Wrap it:` / ` - Possible wrappers` names a concept whose child role accepts the node and gives the JSON to paste, where `<the node at this path>` stands for your node (`details.wrapperCandidates`; `alsoRequired` lists roles you still have to fill). ` - Target '…' is …` lists nodes that fit the reference role (`details.targetCandidates`). A suggestion is structurally accepted only; constraints are checked later by `mps_mcp_check_root_node_problems`. No such line means no structural fix was found: check the role with `mps_mcp_get_concept_details`.
* **`'…' is a featureId …, not a node reference`**: a `featureId` from `mps_mcp_get_concept_details` was given as a reference target. Use that feature's `sourceNode`.
* **`Expected JsonObject but was JsonArray`**: `mps_mcp_update_node` `childJson` takes a single node object; only `mps_mcp_insert_root_node_from_json` and `mps_mcp_update_root_node_from_json` accept a top-level array. Add N children with N `ADD`/`CHILD` calls, or nest them under the parent's blueprint.
* **`Invalid format 'text'. Allowed values: JSON, HTML, PLAIN TEXT`** (`mps_mcp_print_node`): the literal is `PLAIN TEXT`, with a space.
* **Dry-run `is a name, not looked up` warnings**: expected for every name target, including names that exist. Do not rewrite them. Fix only `names no node` (stale `r:`/`i:` id) and `matches no Model.Root` warnings, then check `fixReferences.stillBroken` after the real write. Because a forgotten placeholder that looks like a name passes the dry run, search the blueprint for `TARGET_` before writing.
