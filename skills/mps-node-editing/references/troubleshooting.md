# Node Editing — Troubleshooting

* **`INVALID_JSON` (or `INVALID_REQUEST` for `settingsJson`) with `unbalanced: …`, `unterminated string …` or `unexpected content …`**: a JSON input — a blueprint, a tool's `parameters` object, `settingsJson` — is not valid JSON. The server scans the text outside strings and names the likely cause; it is a diagnosis, not a proof, and the `Parser:` line (`at line L column C path $.children[3]`) shows where the parser itself stopped. When the parser stopped earlier for another reason, the message leads with `Parser: …` and the bracket finding follows as `Further on: …`.
  * `unbalanced: N closer(s) missing at the end of input`: the input ended with brackets still open. Appending the listed closers usually parses but may nest later roles under the wrong node; rebuild the blueprint instead.
  * `unbalanced: ']' at line L column C closes the '{' opened at …`: a `}` is missing before that `]` (or the reverse).
  * `unbalanced: K extra closer(s) after the top-level value ended`: the top-level value was already complete; delete the surplus closers and check that nothing was dropped before them.
  * `unterminated string opened at line L column C`: the input was cut off inside a string, or a `"` inside a string is unescaped (write it as `\"`).
  * `unexpected content after the top-level value`: a second value or text follows the top-level value; send exactly one object or array.
  * **Fix**: do not hand-count brackets. Build a blueprint with `moai_plugin/tools/blueprint.py build` and pass the file it writes under the system temp directory; inline JSON over 4096 characters is rejected anyway, and the error then reports the received length. A `parameters` object or `settingsJson` cannot be a file path, so fix it inline.
* **`Concept 'X' not found at $…`** (a node inside the blueprint) **or `Concept not found: concept='X', …`** (the root of `mps_mcp_insert_root_node_from_json`): the `concept` (or `conceptReference`) names no loaded concept; for a root, only rootable concepts are suggested. `. Closest concepts: A, B, C` and `details.suggestions` (`qualifiedName`, `conceptReference`, `alias`) list the likely ones: a concept of that name in another language, one whose alias is that name, or a near miss in the language you named. Paste a `qualifiedName` into `concept`. No `Closest concepts` means nothing is close: look the concept up by what it does with `mps_mcp_search_concepts` instead of trying more spellings. `… is an interface concept; a node needs a concrete concept` means the name is right but no node can have that concept: use a concrete concept that implements it.
* **`Cannot invoke "JsonElement.getAsString()" because ... is null`**: a required JSON field (like `concept` or `role`) is missing.
* **Notation mismatch**: user-provided textual code may differ from the canonical JSON structure; always map it to the structure defined by the concept.
* **`Unknown property '...'` / `Unknown child role '...'` / `Unknown reference role '...'`**: the JSON blueprint uses a property name or role name that is not defined on the specified concept. Check spelling or use `mps_mcp_get_concept_details` to verify the concept's structure. A whole burst of `Unknown property …` for names the concept does declare, or the error code `LANGUAGE_NOT_BUILT`, means the language runtime is missing: the MoWare languages ship as an MPS plugin, so report a broken installation to the user and do not MAKE the language.
* **`Input file path '...' is not inside the system temp directory`**: every blueprint tool accepts a file only under the JVM system temp directory — `$TMPDIR` (or `/tmp`) on Linux, `%TEMP%` on Windows; a leading `$TMPDIR` or `%TEMP%` is expanded. Copy the file there (`f="${TMPDIR:-/tmp}/blueprint-$$.json"`) or pass the JSON inline (≤ 4 KB). Not a blueprint error.
* **`Concept assignability error at JSON path '…'`**: the node, or the reference target, at that path has a concept the role does not accept. Read the lines after `Role:` before looking anything up. ` - Wrap it:` / ` - Possible wrappers` names a concept whose child role accepts the node and gives the JSON to paste, where `<the node at this path>` stands for your node (`details.wrapperCandidates`; `alsoRequired` lists roles you still have to fill). ` - Target '…' is …` lists nodes that fit the reference role (`details.targetCandidates`). A suggestion is structurally accepted only; constraints are checked later by `mps_mcp_check_root_node_problems`. No such line means no structural fix was found: check the role with `mps_mcp_get_concept_details`.
* **`'…' is a featureId …, not a node reference`**: a `featureId` from `mps_mcp_get_concept_details` was given as a reference target. Use that feature's `sourceNode`.
* **`Expected JsonObject but was JsonArray`**: `mps_mcp_update_node` `childJson` takes a single node object; only `mps_mcp_insert_root_node_from_json` and `mps_mcp_update_root_node_from_json` accept a top-level array. Add N children with N `ADD`/`CHILD` calls, or nest them under the parent's blueprint.
* **`Invalid format 'text'. Allowed values: JSON, HTML, PLAIN TEXT`** (`mps_mcp_print_node`): the literal is `PLAIN TEXT`, with a space.
* **A model diff changes `resolve="…"` attributes you did not edit**: expected. Every node-writing tool saves the model with the reference-text refresh Save All applies, so the first write into a model also rewrites its previously stale texts (for example, of references to a renamed node). References from other models to a renamed node catch up the next time a tool writes into that model, or when it is edited and saved in the IDE. `mps_mcp_alter_nodes FIX_REFERENCES` refreshes the texts of a subtree too, and does not count that as `fixed` or `repointed`.
* **Dry-run `is a name, not looked up` warnings**: expected for every name target, including names that exist. Do not rewrite them. Fix only `names no node` (stale `r:`/`i:` id) and `matches no Model.Root` warnings, then check `fixReferences.stillBroken` after the real write. Because a forgotten placeholder that looks like a name passes the dry run, search the blueprint for `TARGET_` before writing. Rule: `moai:mps-mcp-workflow` ([`references/response-envelope.md`](../../mps-mcp-workflow/references/response-envelope.md#dry-run-response)).
